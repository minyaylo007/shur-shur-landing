# 🍒 SHUR-SHUR · ads-engine — учёт лидов и рекламная аналитика

Маленький постоянный сервис на ace-main (не Vercel, не облако). Node ≥ 22.18, TypeScript
без сборки (встроенное снятие типов), **ноль зависимостей**: HTTP, SQLite (`node:sqlite`),
крипто — встроенные модули Node.

| что | где |
|---|---|
| код | `/opt/ihor/shur-ads/app` (копия `ads-engine/` без тестов) |
| данные | `/opt/ihor/shur-ads/data` (700): `ledger.sqlite` (600), `reports/`, `STOP`, `telegram-outbox.jsonl` |
| ключи | `/opt/ihor/shur-ads/env` (600), имена — в `deploy/env.example` |
| лимиты правил | `/opt/ihor/shur-ads/limits.json` (образец `config/limits.example.json`) |
| порт | **127.0.0.1:8014**, закреплён в `~/maestro/PORTS.md`; адрес не настраивается |
| юниты | `ihor-shur-ads.service` (приём + бот), `ihor-shur-ads-daily.timer` (07:30 Киев) |

## Запуск

```
bash ads-engine/deploy/install.sh        # копия кода, env с новым секретом, юниты, старт
systemctl --user status ihor-shur-ads
curl -s http://127.0.0.1:8014/healthz    # режимы, свежесть данных Meta, флаг остановки
```

Команды (на сервере — из `/opt/ihor/shur-ads/app` с тем же env):

```
node src/cli.ts status | daily | collect | report | rules
node src/cli.ts leads 20                        # id, дата, рынок, статус — без имён и контактов
node src/cli.ts set 1a2b3c4d qualified
node src/cli.ts set 1a2b3c4d lost --reason too_expensive
node src/cli.ts set 1a2b3c4d won --amount 1500 --currency EUR
node src/cli.ts actions | approve <id> | reject <id>
node src/cli.ts stop "причина" | resume
```

## Переменные окружения (только имена)

`LEDGER_HMAC_SECRET` · `SHUR_OPS_BOT_TOKEN` · `SHUR_OPS_CHAT_ID` · `META_ACCESS_TOKEN` ·
`META_AD_ACCOUNT_ID` · `META_DATASET_ID` · `META_CAPI_ENABLED` · `META_CAPI_TEST_EVENT_CODE` ·
`SHUR_ADS_RULES_MODE` · `SHUR_ADS_PORT` · `SHUR_ADS_DATA_DIR` · `SHUR_ADS_LIMITS_FILE` · `SHUR_ADS_FIXTURES`.

Нет ключа — часть работает «сухо», а не падает:

| часть | без ключа | с ключом |
|---|---|---|
| приём `/v1/leads` | 503 `not_configured` | HMAC-SHA256(`ts.тело`), окно ±300 с |
| служебный бот | пишет в `data/telegram-outbox.jsonl` | long polling отдельного бота, только чат `SHUR_OPS_CHAT_ID` |
| Meta Insights | фикстуры (вымышленный кабинет, EUR, Europe/Bucharest) | Graph API **v26.0** (сверено 29.09.2026), только GET |
| Conversions API | выключен | только при `META_CAPI_ENABLED=1` и `consent.ads=true` |
| исполнитель правил | **симулятор всегда** | **симулятор всегда** — слоя записи в Meta нет |

## Что делает

1. **Приём лидов** по договору v1: подпись, идемпотентность по `lead_id` (повтор возвращает тот
   же ответ), дубль — тот же нормализованный контакт за 30 дней, спам-метки (нет контакта,
   ссылка в имени, ≥3 ссылок, ≥5 заявок с контакта за сутки). Имя и контакт — только в базе;
   в журнал, в служебный чат, в отчёты они не попадают.
2. **Воронка** `new → contacted → qualified → proposal → won | lost`. Отказ — с причиной
   (дорого, не наш сегмент, не отвечает, выбрал другого, спам, другое), сделка — с суммой и
   валютой. Кнопки в служебном боте или CLI.
3. **Сбор Meta**: кампании, группы, объявления по дням; расход в валюте кабинета и его часовом
   поясе; каждый прогон перечитывает последние 7 дней (Meta дописывает задним числом).
   Google Ads — только интерфейс-заглушка.
4. **Метрики по рынкам** (Сучава / Тель-Авив / другое): расход, лиды, квал., предложения,
   сделки, CPQL, CAC, конверсии этапов. 95 % интервалы (Уилсон для долей, Пуассон для
   «цены за»), пометка «мало данных». Валюты без явного курса (`fx` в limits.json) не складываются.
5. **Правила**: `observe` (по умолчанию — только рекомендации), `approve` (кнопка в боте),
   `auto` (в пределах лимитов). Ограничители: месячные лимиты всего и по рынку (0 = повышать
   нельзя), шаг ≤ `maxStepPct`, минимум данных, интервал между изменениями, окно запаздывания
   конверсий, фаза обучения, никаких повышений на упавших или старых данных, аварийная
   остановка (файл `data/STOP`, `/stop` в боте или `cli stop`). Журнал «причина → действие →
   результат» с ключом идемпотентности. Пока на сайт→учёт не пришло ни одной заявки, правила
   по лидам молчат (иначе «резать всё» было бы ложным выводом).
6. **Отчёт** раз в день по рынкам с неопределённостью, тревоги: данные старше 36 ч, расход без
   лидов выше порога, включена остановка, нет связи сайт → учёт. Без бота — файл
   `data/reports/ГГГГ-ММ-ДД.txt`.
7. **Conversions API**: события `QualifiedLead` и `Purchase`, `event_id = lead_id`, только
   SHA-256 нормализованных email/телефона, `action_source=system_generated`; ошибки
   повторяются ежедневным прогоном (до 6 дней).

**Связь лида с объявлением** — по UTM: в объявлениях Meta ставить
`utm_campaign={{campaign.name}}` (префикс `sv_` → Сучава, `ta_` → Тель-Авив) и
`utm_term={{adset.name}}`.

## Откат

```
systemctl --user disable --now ihor-shur-ads.service ihor-shur-ads-daily.timer
```

Сайт от этого не ломается: пока `LEDGER_URL` на Vercel не задан, сайт сюда ничего не шлёт, а
когда задан — отказ учёта не мешает доставке заявки в Telegram (договор v1). Код прошлой
установки лежит в `/opt/ihor/shur-ads/app.old`; вернуть — поменять местами каталоги и
`systemctl --user restart ihor-shur-ads`. Данные не трогаются.

Публичный блок Caddy — только заготовка `deploy/caddy/shur-ads.caddy`; в `/etc/caddy` не
ставится этой задачей (ставится по OWNER-RULES п.21, когда сайт начнёт слать заявки).

## Что проверено тестами, а что ждёт настоящих доступов

Тесты: `npm run test:all` (проект `ads`, `ads-engine/test/`), типы — `npm run ads:typecheck`.

| проверено на тестах (подделки) | ждёт настоящих доступов |
|---|---|
| подпись, окно времени, 401/400/413/503, идемпотентность, дубли, спам, права 700/600, нет ПД в журнале и чате | настоящий трафик с сайта (`LEDGER_URL` + секрет на Vercel) |
| бот на поддельном Telegram: карточка без ПД, кнопки, причина отказа, сумма сделки ответом, чужой чат, `/stop`, смещение long polling | живой служебный бот (`SHUR_OPS_BOT_TOKEN`, `SHUR_OPS_CHAT_ID`) |
| чтение Meta на поддельном fetch: v26.0 в адресе, только GET, 3 уровня, по дням, страницы, лиды из actions, перечитывание 7 дней, запись сбоя, токен не в ошибках | настоящий кабинет (`META_ACCESS_TOKEN` c `ads_read`, `META_AD_ACCOUNT_ID`); точные имена action_type для лидов именно этого кабинета |
| метрики: Уилсон, Пуассон, рынки и валюты раздельно, курс только явный | цели CPQL и месячные лимиты в `limits.json` — решение владельца |
| правила: три режима, все ограничители, идемпотентность, одобрение с перепроверкой, исполнитель — симулятор, сеть не трогается | запись в Meta **не реализована намеренно** — отдельное решение |
| CAPI на поддельном fetch: выключен по умолчанию, согласие, хэши, `event_id`, повтор | `META_DATASET_ID`, проверка в Events Manager (`META_CAPI_TEST_EVENT_CODE`) |
| сухой ежедневный прогон на фикстурах пишет отчёт в файл (600) | — |
