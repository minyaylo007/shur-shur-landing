# 🍒 SHUR-SHUR — лендинг. Страница для сессии

Next.js, четыре локали (uk, en, he, ro), заявка уходит в Telegram. Живёт на Vercel,
выкат из `main` конвейером. Это не летопись, а четыре команды и одно правило приёмки.
Подробности процесса — `docs/`.

## Команды

| зачем | команда |
|---|---|
| прогон по умолчанию (каждая правка) | `npm test` — критичный набор, ~1,5 с |
| полный набор (перед слиянием) | `npm run test:all` — ~2 с |
| сборка как в бою | `npm run build` — только перед пушем в `main`; ветки собирает CI |
| живой сайт: пиксель, согласие, «спасибо» | `npm run check:live` — Playwright против shur-shur.com, без локальной сборки, ~1 мин |
| выкат | `git push origin main` → CI → Deploy сам; вручную: `gh workflow run Deploy -f ref=<ветка\|тег\|SHA>` |
| откат | `gh workflow run Deploy -f ref=<предыдущий рабочий SHA>` (самый быстрый путь: выкат уже проверенного коммита) |
| откат слиянием | `git revert -m 1 <SHA слияния>` и пуш — когда нужно убрать код, а не только сборку |

Прогоны только в рамке (инцидент 14.09: pytest на 38 часов положил пользователя):

```
TMPDIR=<tmp вне репозитория> timeout 30m systemd-run --user --scope -q \
  --slice='app-ihor\x2dconductor.slice' -p MemoryMax=2G npm test
```

## Что критично, а что вид

`npm test` гоняет то, чьё падение меняет что-то для человека, для заявки или для выката:
заявка доходит в Telegram, валидация и отказы формы, лимит запросов, четыре локали,
настоящий телефон и готовность каналов, отпечаток сборки. Список — в `vitest.config.ts`
(проект `critical`), там же причина каждой строки.

Остальное (вид: шапка, движение, 404, og-карточка, вес картинок, честность цифр в
тексте) — проект `looks`, 44 теста, едет в CI и на слияние. Тесты здесь не стоят
времени — время стоит переписка и написание самих тестов (треть строк за месяц),
поэтому правило с 13.10.2026 (решение владельца, P-2026-10-13-03):

- **Новые тесты — только на три вещи: заявка, право (PII, согласие, пиксель), выкат.**
  На вид новых тестов не писать; существующий тест вида правится, только если упал.
- `npm run build` перед пушем — только в `main`. Ветку собирает CI, локально не нужно.
- Сессия сама сливает свой PR после зелёного CI и сама выкатывает (OWNER-RULES п.30/31),
  разрешения не спрашивает; отчёт ПОСЛЕ, с командой отката.

Мерили 22.09.2026: полный набор 2,0 с, критичный 1,4 с. Перемерили 13.10.2026 при load 39
на 8 ядрах: критичный 10–16 с, полный 19–22 с, `next build` 71 с — нагрузка машины, не тесты.

## Приёмка

Перемеряется ОДНО главное утверждение задачи плюс `npm test`. Снимки дерева,
диверсии на каждый тест и постраничные перепроверки — только там, где цена ошибки
деньги или брони; на лендинге такой цены нет.

Задание — до 15 строк, отчёт — до 20. Выкат в прод без вопросов (OWNER-RULES п.31),
отчёт ПОСЛЕ и обязательно с командой отката. После законченной задачи — сжатие беседы
(п.32).
